# Ruxt 사용자 가이드

Ruxt는 보안을 최우선으로 설계한 SSH/SFTP 워크스테이션입니다. 이 문서는 처음 설치부터 일상적인 사용까지를 다룹니다. 보안 설계의 근거는 [위협 모델](THREAT_MODEL.md)을 참고하세요.

## 1. 설치와 첫 실행

| 플랫폼 | 방법 |
| --- | --- |
| Windows | 릴리스 페이지의 `ruxt-<버전>-setup.exe`(설치 파일) 또는 `ruxt-<버전>-windows-x86_64.zip`(단일 실행 파일). 추가 DLL이 필요 없습니다. |
| Linux | `ruxt-<버전>-linux-x86_64.tar.gz`를 풀고 `./ruxt` 실행. X11/Wayland 모두 지원합니다. |
| macOS | `ruxt-<버전>-macos-aarch64.tar.gz`(Apple Silicon) 또는 `…-macos-x86_64.tar.gz`. |
| 소스 빌드 | `cargo build --release` ([BUILD.md](../BUILD.md)) |

다운로드한 파일은 릴리스에 함께 올라오는 `SHA256SUMS`로 무결성을 확인할 수 있습니다.

처음 실행하면 화면 잠금 비밀번호를 정할지 묻고(7절), 이어서 **둘러보기**가 뜹니다. 여섯 장의 슬라이드로 접속과 세션, 파일·터널·X11, 터미널 도구, 보안 설정, 단축키를 소개합니다. `다음`/`이전` 버튼이나 `←`/`→` 키로 넘기고, 아래 점을 눌러 원하는 장으로 바로 갈 수 있습니다. 한 번 닫으면 다시 뜨지 않으며, 도구 모음의 `?` → **둘러보기 다시 보기**로 언제든 다시 열 수 있습니다.

그다음 왼쪽에 빈 세션 목록, 위에 도구 모음이 보입니다. 도구 모음을 우클릭하면 각 버튼의 표시를 켜고 끌 수 있습니다. 버튼을 모두 숨겨도 같은 메뉴에서 다시 켭니다. 설정 → 모양 → **언어**에서 한국어/English를 고를 수 있습니다.

## 2. 접속하기

### 빠른 연결
도구 모음의 입력 칸에 `사용자@호스트:포트`를 적고 Enter를 누르면 바로 연결됩니다. 빠른 연결로 만든 세션은 저장되지 않습니다(비밀번호도 저장할 수 없습니다). 자주 쓰는 서버는 세션으로 저장하세요.

### 세션 저장
**+ 새 세션**을 누르면 세션 편집기가 열립니다.

| 항목 | 설명 |
| --- | --- |
| 이름 / 그룹 / 태그 | 목록 표시와 검색에 쓰입니다. 태그는 쉼표로 구분합니다. |
| 호스트 / 포트 / 사용자 이름 | 접속 대상. 사용자 이름을 비우면 현재 PC 계정 이름을 씁니다. |
| 인증 | 자동(에이전트 → 기본 키 파일 → 비밀번호 → 키보드 인터랙티브), 비밀번호, 공개키 파일(OpenSSH·PKCS8·PuTTY PPK), SSH 에이전트, 키보드 인터랙티브(OTP/2FA). |
| 점프 호스트 | 다른 저장 세션을 먼저 거쳐 연결합니다(OpenSSH의 `ProxyJump`). 점프 호스트의 호스트 키·인증·저장된 비밀번호는 그 세션의 설정을 따르며, 점프 호스트 세션에 또 점프 호스트가 있으면 최대 4홉까지 이어집니다. |
| 보안 프로필 | **엄격**(기본): 포스트양자 하이브리드 KEX, AEAD 암호만. **호환**: 오래된 서버용으로 DH 그룹 교환과 CTR 암호를 추가합니다. SHA-1과 CBC는 어느 프로필에도 없습니다. |
| 시작 명령 | 셸이 열린 직후 실행할 명령. |
| 포워딩 | X11 포워딩, 에이전트 포워딩(위험 경고 표시), 터널(-L/-R/-D). |
| 저장된 비밀번호 | 화면 잠금 비밀번호가 있을 때 비밀번호·키 패스프레이즈를 저장합니다(7절). |

세션은 왼쪽 목록에서 더블클릭하거나 오른쪽 클릭 → **연결**로 엽니다. 최근 연결한 세션은 목록 위 **최근** 그룹에 모입니다. 검색 칸은 이름·호스트·그룹·태그를 모두 찾습니다.

### 다른 프로그램에서 가져오기
세션 목록 위의 **가져오기** 메뉴에서

* **OpenSSH 설정** (`~/.ssh/config`): `Host` 블록마다 세션이 만들어지고 `ProxyJump`, `IdentityFile`, `LocalForward`/`RemoteForward`/`DynamicForward`, `ForwardAgent`, `ForwardX11`, `Compression`, `ServerAliveInterval`이 옮겨집니다. 와일드카드 호스트와 `Match` 블록은 건너뜁니다.
* **PuTTY 세션**: Windows 레지스트리(또는 `~/.putty/sessions`)의 저장 세션. 호스트·포트·사용자·키 파일·포트 포워딩·X11/에이전트 포워딩이 옮겨집니다. 비밀번호는 PuTTY도 저장하지 않으므로 옮길 것이 없습니다.
* **Ruxt JSON**: 다른 PC의 Ruxt에서 **내보내기**한 파일. 비밀번호와 패스프레이즈는 내보내기에 포함되지 않습니다.

같은 이름·주소의 세션이 이미 있으면 건너뛰고, id가 겹치면 새 id를 줍니다.

### 호스트 키 확인
처음 접속하는 서버는 **알 수 없는 호스트 키** 창이 뜹니다. 지문(SHA256)과 randomart를 서버 관리자가 알려준 값과 비교한 뒤 **신뢰하고 연결**을 누르세요. 지문은 저장되어 다음부터는 묻지 않습니다.

키가 바뀐 서버는 **호스트 키가 바뀌었습니다** 경고와 함께 연결이 차단됩니다. 서버를 재설치한 것이 확실할 때만 확인란을 체크하고 교체하세요. 중간자 공격일 가능성이 있다면 취소하고 관리자에게 확인하세요.

## 3. 터미널

| 동작 | 키 |
| --- | --- |
| 복사 | `Ctrl+C`(선택이 있을 때), `Ctrl+Shift+C`, `Ctrl+Insert` |
| 붙여넣기 | `Ctrl+V`, `Ctrl+Shift+V`, `Shift+Insert`, 마우스 오른쪽/가운데 버튼 |
| 선택 없이 `Ctrl+C` | 원격 프로그램으로 전달됩니다(인터럽트). |
| 검색 | `Ctrl+Shift+F`, `Enter`/`Shift+Enter`로 이동 |
| 링크 열기 | `Ctrl` + 클릭 |
| 스크롤백 | `Shift+PgUp/PgDn/Home/End`, 마우스 휠 |
| 글꼴 크기 | `Ctrl+휠`, `Ctrl` + `+`/`-` |
| 재연결 | 세션 종료 후 `Enter` |
| 명령어 자동 완성 | `→` 제안 수락 · `Ctrl+↑/↓` 후보 선택 · `Esc` 숨김 |

여러 줄을 붙여넣으면 확인 창이 뜹니다(설정에서 끌 수 있음). 붙여넣는 텍스트에서 ESC 같은 제어 문자는 제거됩니다. **동시 입력**을 켜면 입력이 열린 모든 SSH 탭으로 전송됩니다.

터미널이 아닌 입력란(세션 편집기, 빠른 연결, SFTP 경로 등)에서는 일반적인 `Ctrl+C`/`Ctrl+V`/`Ctrl+X`가 그대로 동작합니다.

### 명령어 자동 완성

**화면 잠금 비밀번호를 정해 두었을 때만** 동작합니다(7절). 명령을 실행하면(Enter) 그 줄이 암호화되어 `history.db`에 저장되고, 다음부터 같은 글자로 시작하는 명령을 입력하면 커서 뒤에 흐린 글씨로 제안이 나타납니다. `→`를 누르면 제안이 채워지고(셸에 글자가 입력됨), 후보가 여럿이면 커서 아래에 목록이 뜹니다(`Ctrl+↑/↓`로 고르거나 클릭). `Esc`는 이 줄에서 제안을 숨깁니다. 같은 서버에서 썼던 명령이 먼저, 그다음 자주·최근에 쓴 순서입니다.

* 저장되는 것은 **화면에 실제로 표시된 글자**입니다. 비밀번호 프롬프트처럼 에코되지 않는 입력은 저장되지 않습니다. `password=`, `token=`, `Authorization:`, `XXX_SECRET=` 같은 비밀처럼 보이는 줄도 건너뜁니다.
* 공백으로 시작하는 명령은 저장되지 않습니다(`HISTCONTROL=ignorespace`와 같음).
* vim 같은 전체 화면 프로그램 안에서는 동작하지 않습니다.
* `history.db`의 각 줄은 화면 잠금 비밀번호로 여는 저장소에 든 키로 암호화됩니다. 잠금이 풀려 있을 때만 기록하고 제안하며, 잠기면 메모리에서 지워집니다. 파일에 평문으로 남는 것은 무작위 줄 번호와 마지막 사용 시각(보관 기간 정리용)뿐입니다.
* 이전 버전이 남긴 평문 기록은 처음 잠금을 풀 때 암호화해 옮기고 평문은 지웁니다. 화면 잠금 비밀번호를 정하지 않았다면 그대로 남아 있으니, 설정 → 명령어 자동 완성의 "명령어 기록 지우기"로 지울 수 있습니다.
* 설정 → 명령어 자동 완성에서 끄거나 기록을 전부 지울 수 있습니다.

### 서버 상태와 서버 정보 창

SSH 탭이 연결되면 하단 상태 표시줄에 CPU, 메모리, 첫 디스크가 흐린 라벨과 얇은 막대, 고정 폭 수치로 나타납니다(기본 5초 주기). 막대는 60% 미만이면 테마 색, 60%부터 주황, 85%부터 빨강입니다. 막대(모니터가 꺼져 있으면 `서버 정보`)를 **클릭**하면 **서버 정보** 창이 열립니다. 부하·스왑·사용자·프로세스는 그 창에 있습니다.

* **연결**: 주소, 보안 프로필, 점프 호스트, 포워딩(X11 신뢰/비신뢰, 에이전트, 터널 수), 상태, 인증 방법, 호스트 키 지문(복사 버튼).
* **서버 상태**: 호스트 이름, OS·커널, 가동 시간, 부하(1/5/15분)와 CPU 수, CPU·메모리·스왑 사용률 막대와 최근 추이 스파크라인, 디스크별 사용량, 사용자·프로세스 수. 창 안에서 모니터링을 끄거나 주기를 바꿀 수 있으며, 이 선택은 그 세션에 저장되어 다음 연결에도 적용됩니다(세션 편집기에서도 주기를 정할 수 있음, 0 = 설정의 기본 주기).

모니터링은 기존 SSH 세션 안에서 `hostname`, `uptime`, `/proc/stat`, `/proc/meminfo`, `df` 같은 **읽기 전용** 명령을 실행합니다(별도 로그인 없음). `/proc`이 없는 macOS/BSD는 일부 항목만 나오고, 셸 실행을 거부하는 서버는 감지해서 그 세션의 모니터링을 멈춥니다. 서버의 감사 로그에 짧은 명령 실행이 남을 수 있으니 원치 않으면 설정 → 서버 상태에서 끄세요.

### 로그 감시 창 (Tail Viewer)

터미널에 `tail -f -n 100 app.log` 같은 명령을 치면 Ruxt가 그 명령을 가로채 **별도의 로그 감시 창**에서 보여 줍니다. 터미널 프롬프트는 비워진 채로 남아 다른 명령을 계속 칠 수 있습니다. SFTP 탐색기에서 파일을 오른쪽 클릭 → **Tail Viewer로 보기 (tail -f)** 로도 엽니다.

* 가로채는 것은 파일을 대상으로 한 단독 `tail` 명령뿐입니다. 파이프(`|`), 리디렉션(`>`), `;`·`&&`, 명령 치환이 들어가면 평소처럼 셸에서 실행됩니다.
* SSH 탭에서는 같은 SSH 연결의 **별도 채널**로 터미널의 현재 폴더에서 명령을 실행하고, 로컬 셸 탭에서는 Ruxt가 파일을 직접 따라 읽습니다. 창을 닫거나 **중지**하면 원격 `tail`도 끝납니다.
* **일시정지**하면 화면은 멈추고 들어오는 줄은 뒤에서 쌓입니다. **자동 스크롤**, **줄바꿈**, **필터**(대소문자 구분 선택, 일치하는 줄만 보기), **전체 복사**, **지우기**, **다시 시작**이 있습니다. 최근 5만 줄까지 보관합니다.
* **감시**: 키워드를 쉼표로 여러 개 넣고, **하나라도 포함 (OR)** 또는 **모두 포함 (AND)** 으로 일치를 셉니다. 일치하면 창이 3초 동안 깜빡이고 줄이 강조되며, 일치 횟수가 버튼에 표시됩니다. **감지 시 이동**을 켜면 자동 스크롤이 꺼져 있어도 새로 일치한 줄로 갑니다. **감시된 줄만** 볼 수도 있습니다.
* **.txt 파일 기록**: 일치한 줄을 고른 텍스트 파일에 실시간으로 덧붙입니다(앞에 시각을 붙이거나 원문 그대로). 이 파일은 Ruxt가 관리하지 않으므로 민감한 로그라면 저장 위치에 주의하세요.
* 창은 별도 OS 창으로 뜨며, **창 고정**으로 Ruxt 창 안에 넣거나 **새 창으로** 다시 뺄 수 있습니다.
* 끄려면 설정 → Terminal → Tail Viewer의 체크를 해제하세요. 그러면 `tail`은 터미널에서 그대로 실행됩니다.

## 4. SFTP 파일 탐색기

도구 모음의 **SFTP**를 누르면 오른쪽에 탐색기가 열립니다. 윈도우 탐색기와 같은 방식으로 쓰면 됩니다.

* **이동**: 뒤로/앞으로/상위 버튼, 폴더 더블클릭, 왼쪽 폴더 트리, 경로 표시줄의 조각 클릭. 경로 표시줄의 빈 곳을 클릭하면 경로를 직접 입력할 수 있습니다(`~` 사용 가능).
* **터미널 따라가기**: 보기 메뉴의 "터미널 작업 폴더 따라가기"가 켜져 있으면 터미널에서 `cd`할 때 탐색기도 따라갑니다(OSC 7 또는 프롬프트 제목 기준).
* **숨김 항목**: 보기 메뉴의 "숨김 항목 (.으로 시작)"을 켜면 점으로 시작하는 파일이 보입니다. 이 선택은 세션마다 저장됩니다.
* **선택**: 클릭, `Ctrl`+클릭(추가), `Shift`+클릭(범위), `Ctrl+A`(전체). 빈 곳 클릭으로 해제.
* **키보드**: `Backspace` 상위 폴더, `Enter` 열기, `F2` 이름 바꾸기, `Delete` 삭제, `F5` 새로 고침, `Alt+←/→` 뒤로/앞으로, 방향키로 이동.
* **정렬**: 열 머리글(이름·수정한 날짜·유형·크기)을 클릭. 폴더가 항상 먼저 옵니다.
* **업로드**: 업로드 메뉴, 또는 Windows 탐색기에서 파일을 창으로 끌어다 놓기. 같은 이름의 파일이 있으면 덮어쓸지 묻습니다. 전송은 임시 이름으로 쓴 뒤 원자적으로 교체되므로 실패해도 원본이 남습니다.
* **다운로드**: 선택 후 다운로드 버튼(저장 위치를 묻습니다). **로컬 창**이 켜져 있으면 로컬 창의 현재 폴더로 바로 내려받습니다.
* **로컬 창**(보기 → 로컬 창): 내 PC의 폴더를 나란히 봅니다. 로컬 창의 항목을 원격 목록이나 폴더로 끌어다 놓으면 업로드, 원격 항목을 로컬 창으로 끌어다 놓으면 다운로드됩니다. 드라이브 메뉴에서 바탕 화면·문서·다운로드·드라이브로 바로 갈 수 있습니다.
* **이동·복사**: 원격 항목을 다른 폴더 행이나 트리 노드로 드래그하면 이동합니다. 오른쪽 클릭 메뉴(또는 `Ctrl+X`/`Ctrl+C`/`Ctrl+V`)로 잘라내기·복사·붙여넣기. 같은 폴더에 복사하면 `이름 - copy`로 만들어집니다. 복사는 서버 안에서 이루어지지만 SFTP에는 복사 명령이 없어 데이터가 클라이언트를 거쳐 흐릅니다.
* **바로 편집**: 파일을 더블클릭(또는 Enter)하면 Ruxt 안의 편집 창에서 열립니다. 고친 뒤 **Ctrl+S** 또는 "저장"을 누르면 서버 파일에 바로 저장됩니다(줄바꿈 형식·권한 유지). 저장하지 않고 닫으면 확인을 묻습니다. 8 MiB보다 크거나 텍스트(UTF-8)가 아닌 파일은 아래 외부 편집기로 엽니다.
* **외부 편집기로 편집**: 오른쪽 클릭 → "편집"을 누르면 로컬 편집기(설정 → 외부 편집기, 비우면 OS 기본 프로그램)에서 열리고, 저장할 때마다 자동으로 업로드됩니다. 서버 쪽에서 파일이 바뀌면 덮어쓰기 전에 알려줍니다. 외부 편집기를 지정하지 않으면 실행 파일·스크립트는 (실행될 수 있으므로) 열지 않습니다.
* **권한**: 항목 하나를 선택하고 권한 버튼 → 8진수(예: `755`) 입력.
* **삭제**: 영구 삭제이며 확인 창이 뜹니다. 디렉터리 심볼릭 링크는 링크만 지우고 대상은 따라가지 않습니다.
* **전송 목록**: 창 아래에 한 줄로 접혀 있고, `완료/전체`를 보여 줍니다. 그 줄을 클릭하거나 위쪽 가장자리를 끌어 올리면 목록이 열리고, 각 전송을 취소할 수 있습니다. 동시 전송은 4개로 제한됩니다.

## 5. 터널

세션 편집기 또는 **터널** 패널에서 추가합니다.

| 종류 | 의미 | 예 |
| --- | --- | --- |
| 로컬 (-L) | 내 PC의 포트 → 서버를 거쳐 대상 호스트:포트 | `127.0.0.1:8080 -> 10.0.0.5:80` |
| 원격 (-R) | 서버의 포트 → 내 PC를 거쳐 대상 | `127.0.0.1:9000 <- 127.0.0.1:3000` |
| 동적 (-D, SOCKS5) | 내 PC에 SOCKS5 프록시 | `127.0.0.1:1080` |

기본적으로 로컬/동적 터널은 루프백(127.0.0.1)에만 바인드됩니다. 다른 PC에서 접근하게 하려면 설정 → 보안에서 허용을 켜고 바인드 주소를 바꾸세요. SOCKS5는 CONNECT만 허용합니다.

## 6. X11 포워딩

원격 GUI 프로그램을 띄우려면 로컬 X 서버가 필요합니다. Ruxt에는 **Cygwin/X(`XWin.exe`)가 `ruxt.exe` 안에 들어 있어** 따로 설치할 것이 없습니다. 처음 X 서버를 켤 때 `%LOCALAPPDATA%\ruxt\data\xserver`에 풀고, 켤 때마다 파일이 바뀌지 않았는지 확인합니다(바뀌었으면 다시 풂). 설정에서 `XWin.exe`를 지정하거나 `ruxt.exe` 옆에 `xserver\` 폴더를 두면 그것을 먼저 씁니다. VcXsrv와 Xming은 더 이상 지원하지 않습니다. Ruxt가 **무작위 인증 쿠키**로 시작합니다. 기본값으로는 Ruxt를 켤 때 같이 켜지지 않습니다. 상태 표시줄에서 직접 켜거나, 세션의 X11 포워딩이 켜져 있고 서버가 아직 없으면 접속할 때 시작합니다(설정에서 변경). 띄우기 직전에 방화벽 인바운드 차단 규칙을 한 번 묻습니다. 거부해도 서버는 켜지고, 우클릭 메뉴에 경고가 남습니다. 클릭하면 Ruxt가 띄운 서버를 켜거나 끄고, 우클릭하면 새로고침·방화벽 규칙·다운로드가 열립니다. 원격 프로그램에 실제 쿠키는 전달되지 않습니다.

**비신뢰 / 신뢰 모드.** 기본값은 OpenSSH의 `ssh -X`와 같은 **비신뢰** 모드입니다. Ruxt가 X SECURITY 확장으로 비신뢰 쿠키를 발급받아 원격 프로그램에 적용하므로, 원격 프로그램은 자기 창만 다룰 수 있고 다른 창의 내용을 읽거나 키보드 입력을 가로챌 수 없습니다. 동봉 `XWin.exe`는 이 확장을 켜서 **직접 빌드**한 것입니다(Cygwin이 배포하는 기본 패키지에는 없음). 일부 툴킷이 비신뢰 모드에서 동작하지 않으면(BadAccess 오류) 세션 편집기에서 **신뢰 모드(-Y)** 를 켜세요. 그러면 `ssh -Y`처럼 원격 프로그램이 로컬 디스플레이 전체에 접근할 수 있으니 믿는 서버에만 쓰세요. 비신뢰 모드를 만들 수 없을 때(예: 설정에서 다른 `XWin.exe`를 지정했는데 SECURITY 확장이 없는 경우)는 포워딩을 거부하고 터미널에 이유를 표시합니다. 비신뢰 인증은 마지막 X 프로그램이 종료된 뒤 7일이 지나면 만료되므로, 아주 오래 열어 둔 세션에서 X 프로그램이 거부되면 다시 접속하세요.

**방화벽.** X.org 서버는 루프백에만 바인드하는 옵션이 없어 TCP 6000+n 포트가 네트워크에 열립니다(쿠키 없이는 접속할 수 없지만 포트 자체는 보입니다). Windows 설치 파일은 관리자 설치 시 `XWin.exe`에 대한 **인바운드 차단 규칙**을 추가합니다. Windows 방화벽은 루프백 트래픽을 걸러 내지 않으므로 Ruxt의 포워딩은 그대로 동작하고 LAN에서는 포트가 닫힙니다. 규칙이 없으면 상태 표시줄의 X 서버 항목을 우클릭하면 경고와 **방화벽 차단 규칙 추가** 버튼(관리자 확인)이 나옵니다.

## 7. 화면 잠금과 저장된 비밀번호

Ruxt 창은 비밀번호 하나로 잠그고, 같은 비밀번호로 세션의 비밀번호·키 패스프레이즈를 암호화해 저장합니다. 따로 기억할 마스터 비밀번호는 없습니다.

처음 실행하면 "Ruxt를 비밀번호로 보호할까요?"라고 묻습니다. 비밀번호를 정하면 **10분 동안 사용하지 않을 때** 창 전체가 잠기고(기본값), 비밀번호를 넣어야 세션으로 돌아갈 수 있습니다. "나중에"를 누르면 잠금을 끈 채로 두고 다시 묻지 않습니다. 이때는 비밀번호를 저장할 수 없습니다. 나중에 설정 → 보안 → 화면 잠금에서 비밀번호를 정할 수 있습니다.

* 화면 잠금 비밀번호가 있으면 Ruxt는 **잠긴 상태로 시작**합니다. 잠금을 풀면 저장된 비밀번호도 함께 열립니다.
* 접속 중 비밀번호 창의 "기억하기 (화면 잠금 비밀번호로 암호화)"를 체크하면 저장됩니다(저장된 세션에서만). 세션 편집기의 "저장된 비밀번호"에서도 넣거나 지울 수 있습니다.
* 저장된 비밀번호는 접속할 때 먼저 조용히 시도됩니다. 키 파일이나 SSH 에이전트로 인증하는 서버에는 패스프레이즈가 걸린 키가 아니면 저장할 것이 없습니다.
* 잠금 시간은 설정 → 보안에서 **10분 단위**로 조절합니다. 0이면 자동으로 잠기지 않습니다(도구 모음의 `잠금` 버튼으로 수동 잠금은 그대로 됩니다).
* 잠겨 있는 동안 SSH 세션과 전송은 계속 실행됩니다. 화면에 보이지 않을 뿐입니다. 저장된 비밀번호는 메모리에서 지워지고, 다음 잠금 해제 때 다시 열립니다.
* 디스크에는 Argon2id 검증값(`applock.bin`)과 암호문(`vault.bin`, Argon2id + XChaCha20-Poly1305)만 저장됩니다. 틀린 비밀번호를 넣을 때마다 다음 확인이 1초씩(최대 5초) 늦어집니다.
* 같은 비밀번호로 **명령어 기록**(자동 완성)도 암호화합니다(3절).
* 비밀번호를 바꾸면 저장된 비밀번호도 새 비밀번호로 다시 암호화됩니다. **잠금을 해제하면 저장된 비밀번호와 명령어 기록도 모두 삭제됩니다.**
* 비밀번호를 잊으면 Ruxt를 종료하고 설정 폴더의 `applock.bin`과 `vault.bin`을 지우면 잠금이 사라집니다. 저장된 비밀번호는 복구할 수 없습니다.

**에이전트 가드 (Windows, 기본 꺼짐).** 도구 모음 또는 설정 → 보안에서 켭니다. 켜면 Ruxt 창이 스크린샷·녹화·화면 공유에서 숨고, 다른 프로그램이 주입한 키보드·마우스 입력은 버려집니다. 화면 잠금 비밀번호가 있으면 그 입력은 창도 잠급니다.

**이전 버전에서 옮겨 오기.** 예전 버전의 "자격증명 금고"는 별도의 마스터 비밀번호를 썼습니다. 화면 잠금 비밀번호로 처음 잠금을 풀 때(또는 잠금 비밀번호를 처음 정할 때) Ruxt가 예전 마스터 비밀번호를 한 번 묻고, 저장된 비밀번호를 화면 잠금 비밀번호로 다시 암호화합니다. 그 뒤로는 마스터 비밀번호를 쓰지 않습니다. "나중에"를 누르면 설정 → 보안의 "저장된 비밀번호 옮기기…"로 다시 할 수 있고, 마스터 비밀번호를 잊었다면 "이전 비밀번호 삭제"로 새로 시작합니다.

### 사용자 지정 테마

설정 → 모양 → **새 테마…** 를 누르면 지금 쓰는 색에서 출발하는 테마 편집기가 열립니다. 왼쪽은 인터페이스 색(패널, 창, 입력란, 줄무늬 행, 버튼 3단계, 글자, 보조 글자, 강조색, 선택, 링크, 경고, 오류, 테두리), 오른쪽은 터미널 색(글자, 배경, 커서, ANSI 16색)이며 색 버튼을 누르면 색상 선택기가 뜹니다. 바꾸는 즉시 창 전체와 열린 터미널에 반영되고, **취소**하면 이전 테마로 돌아갑니다. 이름을 붙여 **저장**하면 설정과 함께 보관되고(최대 32개) 테마 목록에서 고를 수 있습니다.

* **내보내기…**: 선택한 테마를 `이름.ruxt-theme.json`으로 저장합니다. 색은 `#rrggbb` 문자열이라 손으로 고칠 수 있고, 일부 색만 적은 파일도 가져올 수 있습니다(나머지는 말차 기본값).
* **가져오기…**: JSON 파일을 읽어 목록에 추가하고 바로 적용합니다. 같은 이름이 있으면 `(2)`가 붙습니다.
* 기본 테마 12개는 편집기 안의 **시작점** 메뉴로 언제든 다시 불러올 수 있습니다. 이름은 유지되고 색만 바뀝니다.

### 창과 대화상자

모든 창(설정, 세션 편집기, 테마 편집기, 서버 정보, 키 생성, 정보)과 모달(화면 잠금, 비밀번호 옮기기, 호스트 키·비밀번호 프롬프트, 확인)은 Ruxt 창보다 커지지 않습니다. 내용이 길면 본문이 스크롤되고 버튼은 아래에 남으며, 창 모서리를 끌어 크기를 바꿀 수 있습니다. 대화상자의 버튼은 오른쪽부터 **확인(채운 pill) → 보조(테두리 없는 고스트, 마우스를 올리면 옅은 배경) → 취소(글자)** 순서이고, 되돌릴 수 없는 확인은 오류색 버튼입니다. 본창은 1px 테두리 대신 면의 밝기로 터미널과 막대, 활성 탭을 나눕니다.

## 9. 파일 위치

| 파일 | Windows | Linux / macOS |
| --- | --- | --- |
| 설정·세션 | `%APPDATA%\ruxt\config\config.json` | `~/.config/ruxt/config.json` |
| 저장된 비밀번호 | `%APPDATA%\ruxt\config\vault.bin` | `~/.config/ruxt/vault.bin` |
| 호스트 키 | `%APPDATA%\ruxt\config\known_hosts` | `~/.config/ruxt/known_hosts` |
| 감사 로그 | `%LOCALAPPDATA%\ruxt\data\audit.log` | `~/.local/share/ruxt/audit.log` |
| 명령어 기록 | `%LOCALAPPDATA%\ruxt\data\history.db` | `~/.local/share/ruxt/history.db` |
| 원격 편집 사본 | `%LOCALAPPDATA%\ruxt\data\edit\`(인덱싱 제외) | `~/.local/share/ruxt/edit/` |

모든 파일은 소유자만 읽을 수 있게 만들어지며, 설정 파일이 손상되면 `config.json.bad-<시각>`으로 보존됩니다. 감사 로그는 JSON Lines 형식으로 접속·인증·호스트 키·터널·전송·잠금 이벤트를 기록하고 비밀은 담지 않습니다. 감사 로그와 설정 파일은 **평문**이므로(호스트, 사용자 이름, 파일 경로가 보임) PC를 잃어버릴 때를 대비해 BitLocker 같은 디스크 암호화를 켜 두세요. 명령어 기록은 화면 잠금 비밀번호로 암호화됩니다. 감사 로그는 설정 → 보안에서 끌 수 있습니다.

## 10. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| "connection timed out" | 호스트/포트, 방화벽. 호스트 키 창이 열려 있는 동안은 시간 제한이 멈춥니다. |
| 인증 실패 | 인증 방식을 명시해 보세요. 키 파일은 OpenSSH/PKCS8/PPK 형식이어야 하며 암호화된 키는 패스프레이즈를 묻습니다. 에이전트는 Windows OpenSSH 에이전트(named pipe) 또는 `SSH_AUTH_SOCK`을 씁니다. |
| 오래된 서버에서 KEX 협상 실패 | 보안 프로필을 **호환**으로 바꾸세요. 그래도 "no common key algorithm"이면 서버가 `ssh-rsa`(SHA-1) 호스트 키 서명만 지원하는 것이니 **레거시**를 쓰세요(OpenSSH 7.2 이전). |
| X11 프로그램이 "BadAccess"로 죽거나 "untrusted mode unavailable" 메시지 | 세션 편집기에서 **신뢰 모드(-Y)** 를 켜세요(믿는 서버에만). SECURITY 확장이 없는 X 서버도 같은 메시지를 냅니다. |
| 명령어 제안이 안 뜸 | 설정 → 명령어 자동 완성이 켜져 있는지, vim 같은 전체 화면 프로그램 안이 아닌지 확인하세요. 제안은 이전에 실행한 명령에서만 나옵니다. |
| 상태 표시줄에 서버 상태가 없음 | 서버가 exec 요청을 거부했거나(제한된 셸, Windows 서버) 설정 → 서버 상태가 꺼져 있습니다. 서버 정보 창에서 **다시 시도**할 수 있습니다. |
| 한글이 □로 보임 | 설정 → 터미널 → 글꼴에서 한글을 포함한 고정폭 글꼴을 고르세요. UI는 시스템 한글 글꼴을 자동으로 씁니다. |
| 화면이 느리거나 깨짐 | 설정 → 그래픽에서 렌더러를 wgpu로, 또는 하드웨어 가속을 끔으로 바꾸고 다시 시작하세요. |
| X11 프로그램이 뜨지 않음 | 상태 표시줄의 X 서버 표시를 확인. 서버가 `X11Forwarding no`이면 터미널에 거부 메시지가 뜹니다. |
| 감사 로그 확인 | 설정 → 감사 로그 열기 |
